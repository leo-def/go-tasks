# Development Instructions for GoTasks

> Guidelines and rules for Go development in the GoTasks project.
> Use with SPEC.md, README.md, and .agent.md.

## 🎯 Project Overview

- **Purpose**: Modular REST API demonstrating Go best practices
- **Type**: Backend microservice
- **Tech Stack**: Go 1.25+, Gin, GORM, PostgreSQL
- **Architecture**: Modular (13+ domains), dependency injection, repository pattern

---

## 🏗 Architecture Pattern

**Modular Architecture** with clear separation:
- **HTTP Layer**: Gin router, middleware, request/response handling
- **Module Layer**: Each domain (user, task, company, etc.) contains model, repository, service, handler
- **Shared Layer**: Common utilities and middleware

### Directory Structure
```
internal/
├── {module}/           # Each domain module
│   ├── model.go        # GORM models
│   ├── repository.go   # Database operations
│   ├── service.go      # Business logic
│   ├── handler.go      # HTTP handlers
│   └── module.go       # Module initialization
└── core/               # Shared core interfaces
```

## 📂 Module Pattern & Naming

### File Organization
```
internal/{moduleName}/
├── model.go            # Type name: {Module}
├── repository.go       # Type name: {Module}Repository
├── service.go          # Type name: {Module}Service
├── handler.go          # Type name: {Module}Handler
└── module.go           # Function: New{Module}Module()
```

### Naming Conventions

**Packages**
- `internal/{domain}/{feature}` (lowercase, single word preferred)
- Examples: `user`, `task`, `company`, `auth`, `project`

**Types/Structs**
- `PascalCase` for all structs and interfaces
- Repository: `{Entity}Repository` (interface), `gorm{Entity}` (implementation)
- Service: `{Entity}Service` (interface), `gorm{Entity}Service` (implementation)
- Handler: `{Entity}Handler`
- Models: `{Entity}` or `{Entity}Model`

**Functions/Methods**
- `camelCase` for all functions and methods
- Receivers: single letter (e.g., `r *UserRepository`)
- Constructor functions: `NewUserRepository`, `NewUserService`
- Handlers: `(h *UserHandler) GetUser(c *gin.Context)`
- HTTP methods: `Get`, `List`, `Create`, `Update`, `Delete` prefix

**Constants/Variables**
- `UPPER_SNAKE_CASE` for constants
- `camelCase` for variables
- Database fields: `snake_case` in tags, `PascalCase` in struct

### Example Module Structure

```go
// user/model.go
type User struct {
    ID        uint          `gorm:"primaryKey"`
    Email     string        `gorm:"uniqueIndex"`
    Name      string
    CreatedAt time.Time
}

// user/repository.go
type UserRepository interface {
    FindByID(ctx context.Context, id uint) (*User, error)
    FindByEmail(ctx context.Context, email string) (*User, error)
    Create(ctx context.Context, user *User) error
    Update(ctx context.Context, user *User) error
    Delete(ctx context.Context, id uint) error
}

// user/service.go
type UserService interface {
    GetUser(ctx context.Context, id uint) (*User, error)
    CreateUser(ctx context.Context, req *CreateUserRequest) (*User, error)
}

// user/handler.go
type UserHandler struct {
    service UserService
}

func (h *UserHandler) GetUser(c *gin.Context) {
    // HTTP logic
}

// user/module.go
type UserModule struct {
    Repository UserRepository
    Service    UserService
    Handler    *UserHandler
}

func NewUserModule(db *gorm.DB) *UserModule {
    repo := NewUserRepository(db)
    svc := NewUserService(repo)
    hdlr := NewUserHandler(svc)
    return &UserModule{repo, svc, hdlr}
}
```

## 🤖 Instructions for AI Agents

### ✅ DO's

1. **Follow Module Pattern Strictly**
   - Each module has exactly 5 files: model, repository, service, handler, module
   - No exceptions; consistency is key

2. **Use Dependency Injection**
   - Pass dependencies through function parameters
   - Never use global variables
   - Constructor functions return fully initialized objects

3. **Implement Interfaces First**
   - Define repository and service interfaces before implementations
   - Enables testing with mocks
   - Makes contracts explicit

4. **Handle Errors with Context**
   ```go
   // ✅ Good - wrapped error with context
   if err := db.Where("id = ?", id).First(&user).Error; err != nil {
       return nil, fmt.Errorf("failed to get user %d: %w", id, err)
   }
   ```

5. **Use Gin Context for HTTP Concerns**
   - Don't leak Gin context into services
   - Services work with plain `context.Context`
   - Convert to/from HTTP in handlers

6. **Validate Input at Boundaries**
   - Validate in handlers before calling service
   - Use structs with validation tags
   - Return 400 for validation errors

7. **Test Each Module Component**
   - Unit test repository with fixtures
   - Unit test service with mocked repository
   - Integration test handler with test database

8. **Use GORM Hooks for Side Effects**
   - `BeforeSave`, `AfterFind` for model logic
   - Keeps business logic in models

### ❌ DON'Ts

1. **Don't Mix Concerns**
   - ❌ Put HTTP logic in service
   - ✅ HTTP logic in handler, business logic in service

2. **Don't Use Global State**
   - ❌ Global database connection
   - ✅ Pass DB through DI

3. **Don't Leak Database Errors**
   - ❌ Return raw GORM errors to HTTP layer
   - ✅ Wrap and map to domain errors

4. **Don't Make Services Depend on HTTP**
   - ❌ Service imports Gin
   - ✅ Service accepts plain context.Context

5. **Don't Hardcode Configuration**
   - ❌ Database URL in code
   - ✅ Load from environment or config file

6. **Don't Ignore Error Handling**
   ```go
   // ❌ BAD - error ignored
   db.Where("id = ?", id).First(&user)
   
   // ✅ GOOD - error handled
   if err := db.Where("id = ?", id).First(&user).Error; err != nil {
       return nil, fmt.Errorf("failed to get user: %w", err)
   }
   ```

7. **Don't Create Circular Dependencies**
   - ❌ UserService imports CompanyService which imports UserService
   - ✅ Use event patterns or dependency injection

8. **Don't Log Sensitive Data**
   - ❌ Log passwords, tokens, personal data
   - ✅ Log actions, IDs, status, not sensitive values

## 🔄 Common Development Workflows

### Adding a New Module

1. **Create the 5 files** in `internal/{moduleName}/`
   - `model.go` - Define GORM struct
   - `repository.go` - Interface + implementation
   - `service.go` - Interface + implementation
   - `handler.go` - HTTP handlers
   - `module.go` - Initialization

2. **Example: Task Module**
   ```bash
   mkdir -p internal/task
   touch internal/task/{model,repository,service,handler,module}.go
   ```

3. **Define the Model First**
   ```go
   // task/model.go
   type Task struct {
       ID        uint
       Title     string
       Status    string // todo, in_progress, done
       UserID    uint
       CreatedAt time.Time
   }
   ```

4. **Implement Repository**
   - CRUD operations on Task
   - Queries specific to your domain

5. **Implement Service**
   - Business logic using repository
   - Validation and transformation

6. **Implement Handler**
   - HTTP endpoints using service

7. **Register Module** in `cmd/api/main.go`
   ```go
   taskModule := task.NewTaskModule(db)
   // Register routes
   taskModule.Handler.RegisterRoutes(router)
   ```

8. **Write Tests**
   - Unit tests for repository
   - Unit tests for service with mocked repo
   - Integration tests for handler

### Adding a New Endpoint

1. **Add Handler Method** in `{module}/handler.go`
   ```go
   func (h *UserHandler) UpdateUser(c *gin.Context) {
       // Extract ID, validate, call service
   }
   ```

2. **Register Route** in `{module}/module.go`
   ```go
   router.PUT("/users/:id", h.Handler.UpdateUser)
   ```

3. **Add Service Method** if needed
   ```go
   func (s *UserService) UpdateUser(ctx context.Context, id uint, req *UpdateUserRequest) error {
       // Implementation
   }
   ```

4. **Write Tests**
   - Test handler with mock service
   - Test service with mock repository

### Fixing a Bug

1. **Write a Failing Test**
   - Add test case that reproduces bug
   - Verify it fails

2. **Locate the Bug**
   - Is it in handler (HTTP logic)?
   - Is it in service (business logic)?
   - Is it in repository (database access)?

3. **Fix at the Right Layer**
   - Fix in the lowest layer (repository → service → handler)

4. **Verify Test Passes**
   - Run the test that was failing
   - Run all tests to ensure no regression

## 🧠 Go Idioms & Best Practices

### Error Handling Pattern
```go
// ✅ Idiomatic Go error handling
if err != nil {
    return fmt.Errorf("operation failed: %w", err)
}

// Return error as last return value
func (r *UserRepository) GetUser(id uint) (*User, error) {
    // Implementation
    return user, nil  // or return nil, err
}
```

### Context Usage
```go
// ✅ Context for cancellation and timeouts
func (s *UserService) GetUser(ctx context.Context, id uint) (*User, error) {
    select {
    case <-ctx.Done():
        return nil, ctx.Err()
    default:
        // Continue with operation
    }
}
```

### Defer for Cleanup
```go
// ✅ Use defer for resource cleanup
func (r *UserRepository) FindByEmail(email string) (*User, error) {
    rows, err := db.Query("SELECT * FROM users WHERE email = ?", email)
    if err != nil {
        return nil, err
    }
    defer rows.Close()  // Ensure cleanup
    // Use rows
}
```

### Interface Segregation
```go
// ✅ Small, focused interfaces
type Reader interface {
    Read(p []byte) (n int, err error)
}

type Writer interface {
    Write(p []byte) (n int, err error)
}

// Compose larger interfaces
type ReadWriter interface {
    Reader
    Writer
}
```

## 🚫 Forbidden Practices

### 1. Global State
```go
// ❌ BAD
var DB *gorm.DB
var logger Logger

// ✅ GOOD - Inject dependencies
func NewUserService(db *gorm.DB, logger Logger) *UserService {
    return &UserService{db, logger}
}
```

### 2. Mixed Concerns
```go
// ❌ BAD - Service knows about Gin
type UserService struct {
    router *gin.Engine
}

// ✅ GOOD - Service is framework-agnostic
type UserService struct {
    repository UserRepository
}
```

### 3. Ignored Errors
```go
// ❌ BAD
db.Where("id = ?", id).First(&user)
row := db.QueryRow("SELECT ...")

// ✅ GOOD
if err := db.Where("id = ?", id).First(&user).Error; err != nil {
    // Handle error
}
rows := db.QueryRowContext(ctx, "SELECT ...")
```

### 4. Hardcoded Values
```go
// ❌ BAD
dbURL := "postgres://localhost:5432/mydb"
const timeout = 30000

// ✅ GOOD
dbURL := os.Getenv("DATABASE_URL")
const defaultTimeout = 30 * time.Second
```

### 5. Magic Numbers
```go
// ❌ BAD
if len(password) < 8 {
    return errors.New("password too short")
}

// ✅ GOOD
const minPasswordLength = 8
if len(password) < minPasswordLength {
    return errors.New("password too short")
}
```
